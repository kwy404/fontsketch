# Contributing to fontsketch

Thanks for your interest. Pull requests are welcome, from a typo fix in a
guide to a new table in the font compiler.

## Setup

You need Node.js 18.18 or newer.

```sh
npm ci
npm test
```

Before opening a pull request, also run every CI step:

```sh
npm run build
npm run typecheck
npm run lint
npm test
```

## Where things live

| Folder | What it holds |
| --- | --- |
| `src/core/` | Data model, geometry, the font compiler and parser (TTF, OTF, WOFF, WOFF2), hinting, variable fonts, kerning and the Node API |
| `src/scan/` | Handwriting sheet template, photo pipeline (markers, perspective, lighting, cells) and bitmap tracing |
| `bin/` | The `fontsketch` command line tool |
| `docs/app/` | The font editor that runs in the browser |
| `docs/` (everything else) | The website, built by `scripts/build-site.mjs` from `scripts/site/` |
| `assets/` | Mascot, banners, icons and illustrations, generated by `scripts/site/build-art.mjs` |
| `test/` | Vitest suites for core, scan and app |

## Working on fonts

- Units per em are 1000 and the Y axis points up, like in every font format.
  Canvas and SVG code flips the axis when drawing.
- TrueType outlines are quadratic. Cubic input is converted with
  `cubicToQuadratic`, never stored as cubic.
- When you touch the compiler, add a round trip test: build a font, export
  it, parse it back with `parseFont` and compare glyphs, metrics and kerning.
  Test the binary with a second reader too when you can.
- Keep runtime dependencies at zero. The only optional one is `brotli-wasm`
  for WOFF2, loaded lazily.

## Working on the website

- Guides are Markdown files with front matter in `scripts/site/guides/en`
  and `scripts/site/guides/pt`. Run `node scripts/build-site.mjs` to rebuild
  `docs/`, and `node scripts/build-site.mjs --png` to also render the social
  images with a local Edge or Chrome.
- Keep text braces inside code: Voodoo.js reads curly braces in page text as
  expressions.

## House rules

`npm run lint` enforces them in every tracked text file:

- no emoji;
- no en or em dash characters (use commas, colons or parentheses);
- no names of other CSS frameworks.

## Commit style

- Small, focused commits with a short imperative subject, for example
  `Add GPOS pair kerning` or `Fix contour direction for CFF holes`.
- Keep the subject under 72 characters. Use the body to explain why.
- One logical change per pull request.

## Pull requests

Open an issue first for large changes so we can agree on the approach. For
small fixes, just send the pull request. Make sure CI passes.
